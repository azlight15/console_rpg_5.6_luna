# console_rpg_5.6_luna

一个控制台回合制 RPG 项目。

这是原 `Console_RPG` 项目的独立 Luna 重构版本。

## 版本

**Luna v1.5.0**

v1.5 重点解决“技能已经存在，但玩家不知道在哪里学”的问题，同时把主菜单的返回/退出规则统一为数字 0，并继续整理 UI 分区。

### v1.5.0 更新内容

- 主菜单新增“技能管理”入口。
- 新角色保留两个基础技能：重击、火球。
- 新增可学习技能：冰枪、毒刃、旋风斩。
- 技能学习有等级条件和金币费用。
- 学习技能消耗金币，不消耗战斗技能点。
- 战斗技能点仍然只负责释放技能。
- 已学习技能和可学习技能在技能管理界面分开显示。
- 所有新增菜单都使用 0 返回。
- 主菜单重新按冒险、成长、城镇、存档分区，减少功能挤在一起的问题。
- 新增技能学习自动化测试。
- 第一场战斗保证生成普通怪物，从第二场开始才进入 10% 精英怪随机机制。

- `EquipmentManager.cs`：背包、装备和出售交互
- `Skill.cs`：技能数据模型和学习条件
- `SkillSystem.cs`：技能目录、技能学习、技能资源检查与技能执行
- `DamageCalculator.cs`：普通攻击和技能伤害计算
- `Monster.cs`：怪物数据模型
- `MonsterFactory.cs`：怪物选择、等级生成和属性缩放
- `Battle.cs`：回合制战斗流程、奖励、掉落和死亡处理
- `LevelUp.cs`：经验结算与升级流程
- `Heal.cs`：非战斗治疗

- `SaveData.cs`：JSON 存档、读档、删档和旧版本兼容
- `Tests/Console_RPG.Tests`：自动化测试项目

## 技能系统

技能现在分成两个完全不同的阶段：

### 学习技能

从主菜单：

`4. 技能管理`

进入后可以看到：

- 已学习技能
- 当前等级
- 当前金币
- 可学习技能
- 每个技能的学习等级和金币费用

当前技能目录：

| 技能 | 学习等级 | 学习费用 | 战斗消耗 | 冷却 |
|---|---:|---:|---:|---:|
| 重击 | 1 | 免费 | 1 点 | 2 回合 |
| 火球 | 1 | 免费 | 2 点 | 3 回合 |
| 冰枪 | 3 | 80 金币 | 2 点 | 3 回合 |
| 毒刃 | 5 | 120 金币 | 1 点 | 2 回合 |
| 旋风斩 | 7 | 180 金币 | 3 点 | 4 回合 |

**学习技能花金币，释放技能花战斗技能点。**

这样可以避免玩家误以为“买/学技能”和“战斗放技能”是同一种资源。

### 战斗中使用技能

进入战斗后选择：

`2. 使用技能`

这里显示的是玩家已经学会的技能。

技能点不足或技能还在冷却时，不会错误消耗战斗回合。

## 装备系统

装备不会直接修改玩家基础属性，而是通过：

- `FinalAttack`
- `FinalMaxHp`
- `FinalCriticalRate`
- `FinalEvasionRate`

计算最终属性。

装备掉落目前采用三档稀有度：普通、稀有、史诗。

v1.4 起装备可以：

- 查看
- 装备
- 出售
- 强化到 +5

当前穿戴的武器和防具不能直接出售，避免误操作。

## 战斗

玩家可以选择：

1. 普通攻击
2. 使用技能
3. 治疗
4. 撤退

怪物根据玩家等级生成，通常在玩家等级上下 2 级范围内浮动。

第一场战斗强制使用普通怪物，之后才启用 10% 精英怪机制。这样新玩家不会一上来就遇到精英怪。

## 存档

存档系统支持多个本地档案，并保存：

- 玩家等级与经验
- 当前 HP
- 基础属性
- 当前武器和防具
- 完整装备库存
- 已学习技能
- 治疗资源
- 金币
- 技能点

新增字段带默认值，因此旧版存档缺少这些字段时仍可以读取。

技能冷却和状态效果属于当前战斗临时数据，不写入存档。

## 自动化测试

测试项目位于 `Tests/Console_RPG.Tests`，当前覆盖：

- 玩家 HP、治疗、装备最终属性
- 金币与技能点
- 技能学习
- 技能冷却生命周期
- 伤害计算
- 升级
- 技能系统
- 装备出售与强化
- 怪物生成与精英怪行为
- 状态效果
- 存档数据转换与旧档兼容

GitHub Actions 会在 `main` 和 `tests` 分支 push 时自动编译并运行测试。

## 注释策略

注释优先解释“未来的自己为什么会看不懂”，而不是逐行翻译代码。

- 类注释说明职责。
- 关键方法说明设计原因。
- 数值规则说明含义。
- 容易出错的状态转换说明为什么这样处理。

新整理的 Player、Skill、SkillSystem 等核心代码使用普通中文注释，不再依赖 XML 文档格式。

## 代码阅读路线

如果隔了一段时间再回来，可以按：

`Program → Player → Battle → SkillSystem / EquipmentManager → MonsterFactory → SaveData`

这个顺序重新理解。

核心原则仍然是：

**UI/流程负责调用，Player 负责状态，Factory 负责创建，System 负责规则，SaveData 负责持久化。**
